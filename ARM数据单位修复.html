1. 背景与数据链路

系统侧「很多字段为空、单位差 10 倍」的主因在 ARM 采集器协议填充，不在云端解析。

DSP CMD04 (TxBuf)
  → UsartDsp.c  DspDataParsing()  写入 SysParam（量纲混杂：1V / 0.1V / 0.01A …）
  → Collector.c ReadRunParam()    填 RunParamDef @ 0x03E8（协议要求 0.1V / 0.1A / 0.01Hz / 0.01V …）
  → ESP32 心跳 v2 位置数组
  → 云端 heartbeat_v2 v2Scales
  → 管理后台 / App
改法原则：只在 ReadRunParam() 做「SysParam 量纲 → 协议量纲」换算。 SysParam 保持 DSP 原样，避免牵动 LCD、保护逻辑、电量统计。

SysParam 实际量纲（以 DSP TxBuf 为准，勿信旧注释）：

/* ===== ReadRunParam 数据填充（建议整段替换） ===== */

/* ---- PV：1V→0.1V，0.01A→0.1A，1W→0.1W ---- */
pRunParam->Vpv1     = (u16)((u32)SysParam.Vpv1 * 10);
pRunParam->Vpv2     = (u16)((u32)SysParam.Vpv2 * 10);
pRunParam->Ppv      = (u32)SysParam.Ppv * 10;

pRunParam->Buck2Curr= (u16)((u32)SysParam.Ipv2 * 10);

/* ---- 温度：InvertTemp 已是 0.1°C；BoostTemp 为 float °C，×10 正确，保持 ---- */
pRunParam->BoostTemp  = Temperature_Struct.LV_MOS * 10;
pRunParam->InvertTemp = SysParam.InvtTemperature;

/* ---- 输出：1W→0.1W，0.01A→0.1A；负值钳 0 ---- */
pRunParam->OutputWatt = (u32)(SysParam.Pload  < 0 ? 0 : SysParam.Pload)  * 10;
pRunParam->OutputVA   = (u32)(SysParam.Sload  < 0 ? 0 : SysParam.Sload)  * 10;

/* ---- 市电 / 逆变电压频率：1V→0.1V，0.1Hz→0.01Hz，0.01A→0.1A，1W→0.1W ---- */

pRunParam->GridFreq     = (u16)((u32)SysParam.GridFreq * 10);
pRunParam->ACOutputVolt = (u16)((u32)SysParam.VloadA * 10);
pRunParam->ACOutputFreq = (u16)((u32)SysParam.LoadFreq * 10);

pRunParam->ACInWatt = (u32)(SysParam.Pgrid < 0 ? 0 : SysParam.Pgrid) * 10;
pRunParam->ACInVA   = (u32)(SysParam.Sgrid < 0 ? 0 : SysParam.Sgrid) * 10;

/* ACChr / ACDisChr：无独立充电/旁路功率源时，可暂与 ACIn 同源（与现网一致），

pRunParam->ACDisChrWatt = pRunParam->ACInWatt;

/* ---- 电池电压 0.1V→0.01V（现有 *10 正确，保留） ---- */

3. P0 · BusVolt「/10 写反」

P0 严重

当前代码（Collector.c:504 附近）：

pRunParam->BusVolt = SysParam.BusVoltage / 10;   /* 错误 */

算例：母线 410V → SysParam=4100（0.1V）→ 现代码填 410 → 云端 ×0.01 = 4.1V（偏小 100 倍）。

正确：

pRunParam->BusVolt = (u16)((u32)SysParam.BusVoltage * 10);  /* 4100 → 41000 → 410.0V */

4. P0 · 电池电流 / 功率符号拆分

涉及：Collector.c ReadRunParam；以及 UsartDsp.c 中 batChgCurr/batDsgCurr（可删除依赖）

问题：

  • batChgCurr/batDsgCurr 在全工程只有声明、没有赋值，永远是 0。
  • Pbat 可为负（放电），直接赋给 u32 BatDisChrWatt 会变成极大值。

请用下面代码替换原来的 Bat*Watt / BatChgCurr / BatDischgCurr 赋值：

/* 电池功率：SysParam.Pbat 充电为正、放电为负，单位 1W → 协议 0.1W */
if (SysParam.Pbat >= 0) {
    pRunParam->BatChrWatt    = (u32)SysParam.Pbat * 10;
    pRunParam->BatDisChrWatt = 0;
} else {
    pRunParam->BatChrWatt    = 0;
    pRunParam->BatDisChrWatt = (u32)(-(s32)SysParam.Pbat) * 10;
}

/* 电池电流：SysParam.Ibat 已是 0.1A，协议也是 0.1A，只拆符号，不要再 ×10 */
if (SysParam.Ibat >= 0) {
    pRunParam->BatChgCurr    = (u16)SysParam.Ibat;
    pRunParam->BatDischgCurr = 0;
} else {
    pRunParam->BatChgCurr    = 0;
    pRunParam->BatDischgCurr = (u16)(-(s32)SysParam.Ibat);
}

/* 若仍要维护全局 batChgCurr/batDsgCurr（UI 可能用），在这里同步赋值 */
batChgCurr = (SysParam.Ibat >= 0) ? SysParam.Ibat : 0;
batDsgCurr = (SysParam.Ibat <  0) ? (s16)(-(s32)SysParam.Ibat) : 0;
注意：市电/逆变电流（IgridA/IloadA）若现场可能为负，赋给 u16 前同样先取绝对值或钳 0。 正常并网负载场景通常为正，可先钳 0 保证不出现 6 万+ 的异常大电流。

6. P1 · ReadTestRunParam（命令 0x14）

文件：source\Collector\Collector.c　ReadTestRunParam()　约 L1232
P1

若产测/ESP32 仍可能读 0x14，当前有明显错误：

  • ACOutputVolt/Freq 抄成了 VgridA/GridFreq（源错）。
  • BatDisChrWatt = Ibat（电流写入功率字段）。
  • BatChrWatt = Pgrid（源错）。
  • Ppv 未赋值。
  • 电压/频率同样缺 ×10。

建议：生产心跳只保证 0x03 ReadRunParam 正确；0x14 要么与 RUNPARAM 同一套换算，要么明确废弃、ESP32 不要读。
