一、系统概述

辰烁光伏监控系统管理后台（inv-admin-frontend）是面向管理员和渠道商的 Web 管理平台，提供设备全生命周期管理、数据分析、远程控制和系统运维能力。

1.1 系统架构

技术栈：
• 前端：React 18 + TypeScript + Vite + Ant Design 5 + Zustand（状态管理）+ ECharts（图表）
• 后端 API：Go + Gin + PostgreSQL 16 + Redis 7
• 设备通信：MQTT (EMQX) + Kafka + WebSocket
• 部署：Docker Compose + Nginx 反向代理

二、登录与安全

2.1 登录方式

管理后台支持以下登录方式：

  • 手机号 + 验证码：通过短信验证码登录
  • 邮箱 + 密码：适用于海外用户
  • 账号 + 密码：传统登录方式

2.2 安全机制

机制说明
JWT TokenBearer Token 认证，过期自动刷新
RBAC 权限基于角色的细粒度权限控制
操作日志所有操作记录不可删除，保留 90 天以上
会话管理单点登录，异地登录提醒
密码策略最低 8 位，含大小写字母和数字
验证码图形验证码防暴力破解

三、角色与权限

系统采用 RBAC（基于角色的访问控制）权限模型，按组织层级划分角色：

3.1 角色层级

角色级别数据范围主要权限
超级管理员系统级全局数据全部功能，含系统配置、用户管理、组织管理
代理商渠道级下属安装商和终端用户数据管理下属组织、查看辖区设备和告警、OTA 推送
安装商服务商级管辖终端用户数据设备安装调试、参数配置、终端用户管理
终端用户业主级仅自己的设备查看设备数据、告警通知、基本控制

3.2 权限模块

权限点说明默认角色
device:view查看设备列表和详情全部
device:control远程控制设备安装商及以上
device:config修改设备参数配置安装商及以上
alarm:view查看告警记录全部
alarm:manage确认/关闭告警安装商及以上
ota:view查看固件和升级包全部
ota:create上传固件/推送升级安装商及以上
ota:control发布/回退/重试升级代理商及以上
user:manage用户增删改查代理商及以上
org:manage组织架构管理超级管理员
log:view查看操作日志代理商及以上
model:manage设备型号管理超级管理员

3.3 数据隔离

  • 通过 parent_id 实现层级关系（代理商 → 安装商 → 综端用户）
  • 上级角色可查看下级的所有数据
  • 终端用户仅可查看自己绑定的设备
  • 权限矩阵缓存在 Redis 中，实时生效

五、设备管理

「设备管理」页面是有权限查看的所有设备的中心管理入口。

5.1 设备列表

列表展示字段：

字段说明

设备 SN唯一序列号
设备型号关联的设备型号
运行状态在线 / 离线 / 故障（带颜色标签）

绑定用户设备绑定的用户

5.2 筛选与搜索

  • 状态筛选：在线 / 离线 / 故障 / 全部
  • 型号筛选：按设备型号过滤
  • 电站筛选：按所属电站过滤
  • 关键字搜索：按设备名称或 SN 模糊搜索
  • 时间范围：按注册时间、最后上线时间筛选

5.3 设备详情

点击设备进入详情页，包含：

  • 实时数据：所有遥测参数实时展示，5 秒自动刷新
  • 历史数据：日/月/年发电曲线，支持 CSV 导出
  • 告警记录：该设备的告警历史
  • 操作日志：该设备的操作记录
  • 远程控制：控制命令下发面板
  • 设备信息：SN、型号、固件版本、WiFi 信息等

5.4 批量操作

  • 批量升级：选择多台设备推送 OTA 升级
  • 批量参数配置：统一修改多台设备的运行参数
  • 批量重启：远程重启多台设备
  • 批量导出：将设备列表导出为 Excel
  • 批量删除：批量解绑/删除设备

6.3 电站操作

  • 创建/编辑/删除电站
  • 添加/移除设备

  • 导出电站发电数据

7.1 型号列表

字段说明示例

7.2 字段配置（显示参数）

每种型号定义一组「显示字段」，决定前端展示哪些参数：

配置项说明示例
field_key后端标识（对应 MQTT 数据 key）ac_voltage
field_name前端显示名称交流电压
field_type数据类型float / int / string / bool
unit单位V / A / W / kWh / %
sort排序（越小越靠前）10
is_show是否在前端显示true
group_name分组名称交流参数 / 光伏参数 / 电池参数
parse_rule解析规则（数学表达式，x 为变量）x/1000

7.3 控制命令配置

将字段的 is_control 设为 true，该字段会出现在控制页面：

控制类型配置示例
简单开关{"label": "开机", "confirm": true, "confirm_message": "确认开机？"}
数值输入{"label": "功率限制", "input_type": "number", "min": 0, "max": 10000, "step": 100, "unit": "W"}
开关切换{"label": "ECO模式", "input_type": "switch", "confirm": true}

7.4 协议管理

配置 MQTT 数据解析规则：

配置项说明
topic_patternMQTT topic 模式（如 data/ac）
parse_type解析方式：json / modbus / custom
parse_config解析配置 JSON
is_active是否启用
无代码接入：通过型号管理页面配置字段和协议，无需修改代码即可接入新型号设备。

字段说明
告警设备设备名称和 SN
告警类型过压 / 欠压 / 过温 / 离线 等
告警级别紧急（红）/ 警告（橙）/ 信息（蓝）

8.2 筛选与搜索

  • 按状态筛选：未处理 / 已确认 / 已关闭

  • 按时间范围筛选
  • 按告警类型筛选

1
自动触发：系统根据规则自动生成告警记录并推送通知
2
确认告警：管理员确认告警，可指派处理人
3
处理问题：处理人解决问题后更新状态
4
关闭告警：告警状态变更为「已关闭」

8.4 批量操作

  • 批量确认：选择多条告警一键确认
  • 批量关闭：选择多条告警一键关闭
  • 导出告警：将告警列表导出为 Excel

8.5 通知管理

「通知」标签页管理通知规则：

  • 配置通知方式（App 推送 / 短信 / 邮件）
  • 按告警级别配置推送策略
  • 设置通知接收人
  • 查看通知发送记录

九、OTA 固件升级

OTA 管理是系统的核心功能之一，支持从固件上传到批量推送的完整流程。

9.1 固件管理

「固件管理」标签页管理固件文件：

操作说明
上传固件上传 ESP32 或 ARM 芯片固件文件
固件信息版本号、芯片类型、文件大小、SHA256 校验
发布说明填写固件更新内容
版本历史查看所有固件版本

9.2 升级包管理

升级包将多个芯片固件打包为一个业务单元：

  • 创建升级包：选择多个芯片固件，指定升级顺序
  • 设置目标型号
  • 发布升级包（标记为可用）
  • 版本格式：V1.0.0.20260630

9.3 升级推送

推送升级到目标设备：

1
选择目标固件版本或升级包
2
选择目标设备（单台 / 批量 / 按型号 / 按电站）
3
设置升级时间（立即 / 定时）
4
确认并推送，系统创建升级任务

9.4 升级任务

「升级任务」标签页管理升级任务：

  • 查看任务状态：待执行 / 执行中 / 已完成 / 已取消
  • 查看每台设备的升级进度和结果
  • 重试失败的设备
  • 取消未执行的任务

9.5 升级看板

「升级看板」标签页展示升级统计：

  • 升级成功率
  • 各版本覆盖情况
  • 升级失败原因分析
  • 设备固件版本分布

9.6 回退机制

  • 单设备回退：将单台设备回退到上一版本
  • 升级包回退：回退整个升级包的所有设备
  • 回退到已发布版本：回退到最近一次正式发布的版本
升级安全：
• OTA 升级期间确保设备供电稳定
• 升级失败时设备自动回退到上一版本
• 所有升级记录不可删除，供审计追溯
• 敏感操作需要 ota:control 权限

十、远程设置与控制

10.1 远程设置

「远程设置」页面提供设备参数的远程读写能力：

  • 参数读取：从设备读取当前配置参数
  • 参数写入：修改设备运行参数（需专业权限）
  • 参数分组：按交流参数、光伏参数、电池参数、系统参数分组

10.2 命令下发

支持的控制命令：

命令说明通信方式
set_control设置远程控制参数（功率限制、充放电使能等）MQTT
get_params获取设备当前参数MQTT
set_params设置设备参数MQTT
set_alarm告警控制（触发/清除）MQTT
reset设备重置MQTT

10.3 批量设置

「批量设置」页面支持对多台设备统一配置参数：

  1. 选择目标设备（支持多选、按型号筛选）
  2. 选择要修改的参数
  3. 设置参数值
  4. 确认并下发
操作安全：所有远程控制操作均记录在操作日志中，包括操作人、时间、参数和结果。敏感参数修改需要 device:config 权限。

15.2 告警规则

  • 参数超限（电压、电流、温度等超过设定阈值）
  • 通信异常（MQTT 断连、Kafka 消费延迟）
  • 服务异常（API 响应超时、数据库连接失败）

十九、部署与运维

19.1 系统要求

组件要求
服务器Linux（推荐 Ubuntu 20.04+），2 核 4GB 以上
数据库PostgreSQL 16 + TimescaleDB 扩展
缓存Redis 7
消息队列EMQX (MQTT Broker) + Apache Kafka
Web 服务器Nginx（反向代理 + 静态文件服务）
容器Docker + Docker Compose

19.2 部署方式

Docker Compose 部署（推荐）

1
克隆项目代码到服务器
2
配置环境变量（deploy/.secrets/deploy.env）
3
执行 make docker-up 构建并启动所有服务
4
配置 Nginx 反向代理和 SSL 证书

手动部署

1
安装依赖：Go 1.21+、Node.js 18+、PostgreSQL 16、Redis 7
2
执行数据库迁移：psql -f database/schema.sql
3
构建 Go 服务：make build-go
4
构建前端：make build-web
5
启动服务：./deploy/deploy.sh --all

19.3 自动部署

支持 Git Polling 和 Webhook 两种自动部署方式：

  • Git Polling：服务器定时拉取 Git 仓库，检测到更新自动部署
  • Webhook：Git 推送时触发 Webhook，服务器收到通知后自动部署

19.4 日常运维

操作命令
查看服务状态make docker-logs
重启服务make docker-down && make docker-up
数据库备份deploy/scripts/backup.sh
数据库维护deploy/scripts/db_maintenance.sh
查看日志journalctl -u inv-monitor -f
监控脚本deploy/monitor.sh

19.5 备份策略

  • 数据库：每日自动备份，保留 30 天
  • 配置文件：版本控制管理
  • 固件文件：对象存储备份
  • 日志：集中日志管理，保留 90 天
安全提醒：
• deploy/.secrets/ 目录包含敏感配置，禁止提交到版本控制
• 定期轮换 JWT 密钥和数据库密码
• 启用 HTTPS，禁止 HTTP 明文传输
• 限制数据库和 Redis 的网络访问范围
