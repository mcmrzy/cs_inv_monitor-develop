# L10 BLE 多模块本地 OTA 设计

状态：用户已确认实施（2026-09-24）

## 目标与边界

手机 App 通过已建立的 L10 BLE 会话，分别升级 ESP、ARM、DSP、BMS 固件。ESP 固件新能力使用 v1.0.10；已经生成的 v1.0.9 本地发布包保持原样，不复用版本号，也不据此宣称已经上架。用户已实测云端经 ESP 升级 ARM/DSP/BMS；本设计复用其 IAP 安装路径，不改云端升级协议。

本期只为 DSP/BMS 增加 BLE 本地通道，不开放这两个模块的 Wi-Fi 热点通道，不自动迁移设备分区表，不改变固件签名策略。旧设备可能仍使用 384 KiB 缓存分区；软件升级不能改变既有分区布局。容量不足必须拒绝，不得覆盖其他分区或把上传完成显示成升级成功。

## 端到端契约

1. 后端固件资源 `supported_channels` 对 ESP/ARM 仍返回 `remote, ble, wifi_ap`；对 DSP/BMS 返回 `remote, ble`。服务端仅表达该固件可用的传输方式，不代替现场设备能力判断。已有本地结果接口继续以 `target_chip` 和 `new_version` 更新对应模块，不能把 DSP/BMS 写入 ARM 字段。
2. ESP v1.0.10 的 BLE INFO `supported_upgrade_modules` 声明 `communication_module`、`system_controller`、`dsp_controller`、`bms`。`ota.ctrl.body.target` 分别映射到 ESP/ARM/DSP/BMS。保留现有 `dsp` 别名；BMS 的规范线值为 `bms`。未知目标仍拒绝。
3. App 的 ESP/ARM 旧设备兼容路径保持不变。DSP/BMS 必须同时满足：资源声明 `ble`，连接已就绪，BLE INFO 明确包含目标模块，才允许发送 `ota.ctrl`。缺少能力字段、字段不合法或目标未列出时，DSP/BMS 在上传前给出“不支持此模块的 BLE 升级”提示；不能把 BLE 写入异常当作升级结果。不得仅凭 ESP 版本字符串猜测能力。
4. App 复用 `BleDeviceSession`/`BleOtaLease`，逐块 `ota.data` 和 `accepted_offset` ACK 契约不变。设备的 `failed`、`succeeded` 与目标模块关联；上传 100% 仅表示传输结束。非 ESP 的 IAP 完成不要求 ESP 重启，轮询窗口须覆盖最慢 BMS 安装时间，且不能在用户仍能看到安装进度时提前超时。
5. App 不再将 BLE INFO 中的 ESP `firmware_version` 同时填充为 ARM/DSP/BMS 版本。结果上报只在目标升级状态为 `succeeded` 后进行，`target_chip` 使用原模块名，`new_version` 使用本次目标镜像版本；界面将其描述为“升级目标版本”，不得声称已独立回读目标模块版本。若设备状态中有可信的目标模块回读版本，可优先显示该版本；未知时不冒充 ESP/ARM 版本。

## 设备容量与错误处理

ESP 在 ARM/DSP/BMS 流式暂存开始前检查实际 `/cache` 可用空间，保留现有 `镜像大小 + 16 KiB` 安全余量；容量不足时立即结束会话并通过 OTA 状态返回稳定的 `INSUFFICIENT_STORAGE` 结果码。App 将其翻译为“设备缓存空间不足，请先完成分区迁移或选择更小的固件”，同时展示必要的诊断大小信息；不能继续发数据或自动改走云端。文件超过模块大小上限仍用现有 `FILE_TOO_LARGE` 类错误，不能混同缓存不足。

旧 384 KiB 缓存布局对 393,200 字节 DSP 镜像不足，因为仅镜像加安全余量就需 409,584 字节；这类设备需单独的一次性有线分区迁移。v1.0.10 的普通 App OTA 只更新应用分区，不会更新分区表。针对缓存拒绝，App 显示失败并保留可诊断的状态，不上报成功。

连接中断、取消、设备忙、目标不支持、哈希校验失败等现有失败路径继续以最终设备状态或明确传输异常表示。手机网络/蓝牙断开时不得伪造成功；未知最终结果保持未知，允许用户重新连接查询设备状态。设备接受 BMS manifest 之前必须完成相同的型号、大小、哈希和安全检查，不因新目标绕过现有验证。

## 实现边界与验证

- ESP：INFO 能力列表、BLE 目标解析、容量错误码和状态传播。IAP UART 安装代码只作必要的错误分类调整，不重写已测试的云端 ARM/DSP/BMS 流程。
- 后端：只调整目标模块的通道元数据及对应服务测试；不增加数据库列或新接口。
- App：资源/下载筛选、BLE 目标能力预检、目标版本映射、结果与容量错误文案。Wi-Fi AP 的 ESP/ARM 行为维持原样。
- 测试覆盖四模块通道矩阵、旧设备 INFO、BMS 目标线值与拒绝路径、容量不足早退、目标版本上报、BLE ACK/状态、慢速 BMS 安装轮询。运行 ESP host tests 与 IDF build、Go OTA 相关测试及构建、Flutter 测试及分析；构建与模拟测试不替代真机升级。
- 发布顺序：先生成并核对 v1.0.10 的版本、尺寸、SHA-256 与清单，保留 v1.0.9 文件；后端能力与 App 开关须与 v1.0.10 设备能力预检配合上线。上架、部署、刷机、实体机 BLE 四模块升级分别留证；没有完成的阶段明确报告，不标为已验证。
