# 系统监控运行异常

## 目标与范围

用户确认将服务器错误接入现有系统监控。新增运行异常页签，与操作审计并列。首期明确覆盖 business-api 请求错误，不声称覆盖网关、设备服务或 PostgreSQL 全量日志。不执行生产数据库修复或部署。

## 方案

利用现有 Redis 保存最近 24 小时、最多 1000 条脱敏 API 错误，避免在数据库故障时依赖新增数据库日志表。相比单进程内存可跨 API 重启保留；相比新增日志平台无需引入部署组件。Redis 无法读取时明确显示未知，计数只代表保留样本。

Gin 中间件生成服务端请求 ID，捕获 HTTP 5xx、response 包产生的业务 5xx 及恢复后的 panic。只保存方法、路由模板、时间、状态、耗时、错误分类和 SQLSTATE；数据库缺列/缺表仅提取标识符。不保存路径参数、查询串、请求/响应正文、头或数据库 Detail。电站失败分支附带原始 error 给中间件分类，不向 App 泄露。

Handler → Service → Repository 提供只读监控快照。Redis 有序集合在读写时原子清理超龄事件并限制容量，独立客户端启用 context 超时、禁重试，写入使用 200ms 截止期限，失败不改变业务响应；结构化日志仍作为备用证据。管理员列表按同类异常合并，展示首末时间、次数、最后请求 ID。监控接口同时在 API 网关注册。

数据库检查独立查询 information_schema，核对电站实时功率依赖及市电采样字段的实际存在和类型。检查失败显示 unknown，缺失显示 degraded，不以 schema_migrations 代替实际检查。不自动改表。

全局运行错误只对已认证 is_system_admin 开放，组织管理员不可读取。前端隐藏无权页签，后端再次校验。

## 验收

- 缺 ac_input_power 的电站查询失败生成可搜索、可合并的数据库缺列异常。
- HTTP 500、业务 code=500、panic 被记录；成功和 4xx 不记录。
- 伪造请求 ID、参数、凭据和 SQL Detail 不进入异常记录。
- 缺字段即使迁移已登记，结构检查仍为 degraded。
- Redis/数据库检查故障显示未知，不能显示为零异常或健康。
- 多条重复异常、限量/过期、鉴权与前端异常展示有行为测试。
