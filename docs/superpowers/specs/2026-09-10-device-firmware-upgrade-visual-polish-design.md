# 设备固件升级视觉优化设计

## 目标

在不改变已确认信息架构、接口和固件模块命名的前提下，降低当前页面“大面积深色渐变 + 重复白卡”的模板感，让设备固件升级页面与 App 已有“小烁”品牌视觉衔接，同时避免插画喧宾夺主。

本轮不处理“关于我们”页面的图片抠图问题；该问题已单独记录为后续待办。

## 视觉方向

采用品牌插画型方案。设备固件升级首页只使用一张小烁 OTA 插画，表现查看设备固件状态与无线更新的场景。图片必须为透明背景 PNG，不带黑边、白边、底色、文字、水印或阴影画布。

实施时曾基于现有角色生成两张专用候选图，但自动检查确认两张均为 RGB 棋盘背景，没有真实 alpha 通道，因此全部拒绝且不进入仓库。最终复用项目已存在并由 `CsergyAssets.xiaoshuoOtaGuide` 集中声明的 `xiaoshuo_ota_1536x1024.png`；本轮不新增、不覆盖也不重新抠取图片资源。

## 首页

- 顶部由深蓝整块 Hero 改为浅蓝品牌信息区，左侧显示“固件状态概览”、说明和接口 `total` 返回的设备总数，右侧显示专用透明插画。不得用当前已加载分页计算或展示全量在线设备数量。
- 插画只承担品牌识别和页面主题表达，不承载状态或操作；文本与按钮不绘制进图片。
- “我的设备”继续作为主内容。设备卡保留设备名称、型号、序列号与在线状态，但减少阴影和描边，使用轻量表面色区分层级。
- “检查全部更新、近场连接升级、固件资源、全部更新记录”四项既有能力继续以 2×2 网格保留在设备列表下方，路由分别保持 `/ota/check-all`、`/local-upgrade`、`/firmware-library`、`/upgrade-history`，使用统一尺寸的功能图标和柔和主题色。
- 加载、空状态、错误和分页逻辑保持不变。

## 设备详情

- 顶部设备摘要使用轻量品牌渐变，不重复放人物插画，避免一页多图造成活动页感。
- 设备信息维持两列网格；固件详情维持 2×2 模块卡；更新日志维持时间线。
- 四个模块继续显示“通信采集、系统主控、功率控制、电池管理”，不显示内部芯片缩写。
- 版本、在线状态与历史数据只展示接口真实返回值，不从插画或视觉状态推断业务能力。

## 检查固件更新入口

- 删除详情页 `bottomNavigationBar` 中的悬浮式固定按钮。
- 在固件更新日志之后、页面内容最末尾放置普通全宽主按钮。
- 按钮属于 `ListView` 文档流，用户滚动到页面底部后看到，不遮挡日志，也不随屏幕悬浮。
- `/ota/:sn` 路由保持不变。仅在线设备可以点击检查按钮；离线设备按钮禁用并在按钮上方显示“设备离线，暂时无法检查”。
- 在线状态优先采用详情接口显式返回的 `online_status.online`。该字段为 `false` 时不得再被数据库 `device.status` 覆盖；仅当实时字段缺失时才回退到 `status == 1 || status == 2`。

## 浏览器预览

同步更新 `ota-final-flow.html`：首页使用浅色插画型 Hero，详情页按钮移入滚动内容底部。预览只用于视觉确认，Flutter 实现仍以真实 Widget、主题、本地化和测试为准。

## 验证

- 检查实际发布资源包含 PNG 透明信息；隔离工作树若只有 Git LFS 指针，则必须保留 `errorBuilder` 并在已拉取 LFS 资源的工作区验证实际文件。
- Flutter Widget 测试验证首页可加载插画，四个入口仍存在。
- Widget 测试验证详情页没有 `bottomNavigationBar`，滚动至日志底部后可找到“检查固件更新”。
- Widget 测试验证显式实时离线状态优先于数据库在线状态，且离线时按钮不可点击并显示原因。
- 使用 390×844 小屏运行页面测试，检查 Hero、2×2 网格和底部按钮无溢出。
- 运行 OTA 测试目录、相关静态分析和差异检查；不把“关于我们”图片修改带入本次提交。
