🔍 问题诊断

测试设备（MASS-TEST-*）之前通过API接口注册，但遥测数据未写入数据库。经过深入分析，发现以下根本原因：

  • 问题1：MQTT消息转发链路不通
    EMQX webhook未配置，MQTT消息无法通过mqtt-kafka-bridge转发到Kafka，导致device-server无法消费设备数据。
  • 问题2：API路径不写入时序数据
    DeviceDataBatch函数只更新last_online_at字段，不写入device_telemetry_3min表，导致触发器无法更新device_latest_state。
  • 问题3：Viper配置优先级问题
    viper.ReadConfig会覆盖之前通过BindEnv获取的环境变量值，导致config.docker.yaml中的空值覆盖了环境变量中的INTERNAL_KEY。
  • 问题4：Heartbeat消息格式不匹配
    测试脚本使用对象格式发送heartbeat，但device-server要求严格的V1数组格式（ac:8, bat:23, pv:7, sys:11, eng:12, cells:2）。

🛠️ 修复方案

1. 修复Viper配置优先级

在 device-communication/internal/config/config.go 的 ReadConfig 之后重新设置环境变量：

// Re-apply environment variables after ReadConfig to ensure env vars // take precedence over config file values if v := os.Getenv("INTERNAL_KEY"); v != "" { viper.Set("backends.internal_key", v) } if v := os.Getenv("API_SERVER_URL"); v != "" { viper.Set("backends.api_server", v) }

2. 创建Kafka模式测试脚本

修改 mqtt_simulator.py，添加 send_via_kafka 函数，直接向Kafka发送符合V1格式的heartbeat消息：

# V1 Heartbeat 格式定义 ac = [voltage_ac, current_ac, power_ac, apparent_power, 50.0, 0.95, 50.0, 2.0] # 8 elements bat = [soc, soh, voltage, current, power, ...] # 23 elements pv = [pv1_voltage, pv1_current, pv1_power, 0, 0, 0, 1] # 7 elements sys = [work_state, fault_code, alarm_code, temp, ...] # 11 elements eng = [daily_pv, total_pv, ...] # 12 elements cells = [cell_voltages, cell_temperatures] # 2 arrays heartbeat_payload = { "t": int(time.time()), "v": 1, "data": {"ac": ac, "bat": bat, "pv": pv, "sys": sys, "eng": eng, "cells": cells} }
