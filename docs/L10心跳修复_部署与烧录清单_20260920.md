## 2. ESP 固件烧录 / OTA

**发版前**

- [ ] 递增固件版本号（版本记录占唯一键，必须比线上大）
- [ ] 确认两个新常量为"补偿"档：`ARM_FW_CONTRACT_UNITS_FROM = 0xFFFF`、`ARM_UNSUPPORTED_FIELDS_IMPLEMENTED = 0`（当前厂家 ARM 未修，必须保持此档）
- [ ] 打包（release.ps1，pwsh 执行；注意 x86_64 排除与文件无 BOM 等既有坑）

**烧录/推送**

- [ ] 上传固件到平台固件库 → 按设备推送 OTA（或现场本地烧录）
- [ ] 建议先单台灰度（例：H1ZZX0023900002P），确认无误再批量

**单台验证（关键）**

- [ ] 串口/日志出现 `ARM fw=0xXXXX → units=compensate`（证明走补偿模式）
- [ ] 心跳字段合理：母线 ≈373.50V、负载率 ≈100%、电池 ≈49.00V/-133.4A、输出 228.0V/49.70Hz、PV 电压按实接
- [ ] 逆变温度 ≈43.0°C（不再是 2883584VA 之类的垃圾）
- [ ] 未实现字段显示 --（inv_current、三个插槽位）

**回滚**：重新推送上一版固件（平台保留历史版本）。

## 3. 与厂家 ARM 的联动（重要）

厂家修好 ARM 后（见问题清单 §5 期望单位契约表）：

1. 把 `ARM_FW_CONTRACT_UNITS_FROM` 改成厂家给出的版本号（例 `0x0102`）→ ≥ 该版本自动直传，混装期旧固件仍走补偿，**无需再改代码**；
2. 若厂家同时实现了 InvCurr/PvTemp/TransformerTemp/并机插槽位，把 `ARM_UNSUPPORTED_FIELDS_IMPLEMENTED` 置 1；
3. 同步执行迁移 124 的 `down`（恢复这 10 个字段的字段能力）；
4. 用一条真实心跳核对"期望单位契约表"逐行一致后再批量。
