1. 协议概述

本协议定义了GD32F30x逆变器系统中，主控板（ARM）与数据采集器之间的通信规范。协议基于串口（USART）通信，采用PPP帧格式进行数据封装，并使用TEA加密算法保障数据安全。

1.1 协议特性

  • 通信接口：USART串口
  • 帧格式：PPP协议帧（0x7E定界符）
  • 加密方式：TEA（Tiny Encryption Algorithm）双重加密
  • 校验方式：CRC32校验
  • 数据字节序：小端序（Little-Endian）
  • 最大帧长：1088字节

1.2 系统架构

3. 帧格式定义

3.1 命令帧结构

采集器命令帧采用紧凑的二进制格式，所有字段按1字节对齐：

Header
CmdLen
CMD
Param1
Param2
Data[]
CRC32
字段 偏移 大小 描述
Header 0 1字节 帧头标识，固定为 0xAA
CmdLen 1 2字节 命令总长度（字节），必须为4的倍数
CMD 3 1字节 命令类型代码
Param1 4 2字节 参数1（起始地址/索引）
Param2 6 2字节 参数2（数据长度/值）
Data[] 8 变长 数据负载，长度 = CmdLen - 8
CRC32 CmdLen-4 4字节 CRC32校验值（覆盖整个帧）
重要约束：
  • CmdLen 必须 ≥ 8 且为 4 的倍数
  • Header 必须为 0xAA
  • CRC32校验覆盖从帧头到CRC字段前的所有数据

3.2 CRC32计算

// CRC32计算伪代码
crc32 = CRC32_HW((u32*)frame, 0xFFFFFFFF, CmdLen >> 2);

// 将CRC32存入帧尾（小端序）
data[CmdLen-8] = crc32;
data[CmdLen-7] = crc32 >> 8;
data[CmdLen-6] = crc32 >> 16;
data[CmdLen-5] = crc32 >> 24;

4. PPP帧封装

4.1 PPP帧格式

原始命令帧在发送前需要进行PPP封装，使用0x7E作为帧定界符：

0x7E
封装数据
0x7E

4.2 转义规则

PPP封装过程中，需要对特殊字符进行转义处理：

原始字节 转义序列 说明
0x7E 0x7D 0x5E 帧定界符转义
0x7D 0x7D 0x5D 转义符转义

4.3 封装算法

function PppPack(dstBuf, srcBuf, srcLen):
    dstBuf[0] = 0x7E  // 起始符
    count = 1
    
    for each byte in srcBuf:
        if byte == 0x7E:
            dstBuf[count++] = 0x7D
            dstBuf[count++] = 0x5E
        else if byte == 0x7D:
            dstBuf[count++] = 0x7D
            dstBuf[count++] = 0x5D
        else:
            dstBuf[count++] = byte
    
    dstBuf[count++] = 0x7E  // 结束符
    return count

4.4 解封装算法

function PPPFrameCmdReceive(AcData, RcvData):
    switch AcData.status:
        case WAITRECEVIE:
            if RcvData == 0x7E:
                AcData.status = ISRCVING
                AcData.length = 0
        
        case ISRCVING:
            if AcData.length > (FRAMLEN-1):
                // 帧长度超限，重置
                AcData.status = WAITRECEVIE
                AcData.length = 0
            
            if RcvData == 0x7E:
                if AcData.length != 0:
                    AcData.status = RCVFINISH  // 帧接收完成
            else if RcvData == 0x7D:
                // 转义符，等待下一个字节
                AcData.Flg7E = 0x7D
            else:
                if AcData.Flg7E == 0x7D:
                    // 处理转义序列
                    if RcvData == 0x5E:
                        AcData.RCdata[AcData.length++] = 0x7E
                    else if RcvData == 0x5D:
                        AcData.RCdata[AcData.length++] = 0x7D
                    AcData.Flg7E = 0
                else:
                    AcData.RCdata[AcData.length++] = RcvData

5. 数据加密机制

5.1 加密算法

协议采用TEA（Tiny Encryption Algorithm）进行数据加密，使用双重加密机制：

TEA算法特点：
  • 块加密算法，块大小为64位（8字节）
  • 密钥长度为128位（16字节）
  • 加密轮数可配置
  • 实现简单，适合嵌入式系统

5.2 加密流程

原始数据帧
第一次TEA加密（使用FrameKey）
生成动态密钥（TempKey）
第二次TEA加密（使用TempKey）
附加密钥片段
PPP封装发送

5.3 密钥管理

// 密钥生成伪代码
u32 TempKey[4];

// 复制基础密钥
memcpy(TempKey, FrameKey, 16);

// 使用系统嘀嗒定时器生成动态部分
TempKey[3] = SysTick->VAL;
TempKey[2] = ~TempKey[3];

// 第一次加密（使用FrameKey）
EncryptData(data, FrameKey, dataLen);

// 第二次加密（使用TempKey）
EncryptData(data, TempKey, dataLen + 8);

// 附加密钥片段到数据末尾
memcpy(data + dataLen + 8, &TempKey[2], 8);

5.4 解密流程

// 解密伪代码
u32 TempKey[4];

// 第一次解密（使用FrameKey）
DecryptData(data, FrameKey, dataLen);

// 提取密钥片段
memcpy(TempKey, FrameKey, 8);
memcpy(&TempKey[2], data + dataLen - 8, 8);

// 第二次解密（使用TempKey）
DecryptData(data, TempKey, dataLen);

8. 通信流程

8.1 读取参数流程

采集器发送读取命令
READ_CTRLPARAM / READ_RUNPARAM
逆变器接收并PPP解封装
TEA双重解密
校验Header和CRC32
解析命令并读取参数
构建响应帧
TEA双重加密
PPP封装并发送

8.2 写入参数流程

采集器发送写入命令
WRITE_CTRLPARAM
逆变器接收并PPP解封装
TEA双重解密
校验Header和CRC32
验证参数范围
写入参数到EEPROM
更新DSP参数
发送状态响应

8.3 连接管理

系统使用CollectorConnect变量管理连接状态：

  • 每收到有效命令，CollectorConnect重置为1200（约120秒）
  • 每100ms递减一次
  • 递减到0表示连接超时
  • 可用于检测采集器在线状态

9. 示例报文

9.1 读取控制参数示例

读取输出优先级（地址0x0000）和最大充电电流（地址0x0001）：

原始帧（未加密）：
AA 10 00 01 00 00 04 00 [CRC32]

字段解析：
- Header: 0xAA
- CmdLen: 0x0010 (16字节)
- CMD: 0x01 (READ_CTRLPARAM)
- Param1: 0x0000 (起始地址)
- Param2: 0x0004 (读取4字节，2个参数)
- Data: 空
- CRC32: 校验值

加密后帧（示意）：
[加密数据...] [密钥片段]

PPP封装后：
7E [转义后的加密数据] 7E

9.2 写入控制参数示例

设置输出优先级为3：

原始帧（未加密）：
AA 0C 00 02 00 00 02 00 03 00 [CRC32]

字段解析：
- Header: 0xAA
- CmdLen: 0x000C (12字节)
- CMD: 0x02 (WRITE_CTRLPARAM)
- Param1: 0x0000 (地址)
- Param2: 0x0002 (写入2字节)
- Data: 0x0003 (值=3)
- CRC32: 校验值

响应帧（成功）：
AA 0C 00 02 00 00 01 00 00 00 00 00 [CRC32]

读取电池电压和SOC：

原始帧（未加密）：
AA 10 00 03 62 03 04 00 [CRC32]

字段解析：
- Header: 0xAA
- CmdLen: 0x0010 (16字节)
- CMD: 0x03 (READ_RUNPARAM)
- Param1: 0x0362 (地址=0x03E8 + 偏移)
- Param2: 0x0004 (读取4字节)

响应数据包含：
- BatVolt: 电池电压 (0.01V)
- BatterySOC: 电池SOC (%)

10. 错误处理

10.1 状态码定义

状态码 名称 描述
0 SUCCESSFUL 执行成功
1 CHECK_ERR 校验错误
3 WAIT_TIMEOUT 等待超时（设备号不为0时设备无响应）
7 EXEC_FAIL 执行失败（如写入Flash错误）

10.2 常见错误场景

场景 处理方式
Header不是0xAA 静默丢弃，不响应
CmdLen不合法 静默丢弃，不响应
CRC32校验失败 静默丢弃，不响应
参数地址越界 静默丢弃，不响应
参数长度为0或奇数 静默丢弃，不响应
接收超时（10ms） 重置接收状态机
帧长度超过1088字节 重置接收状态机

10.3 超时管理

// 接收超时处理（每10ms调用一次）
void InvRxTimeOutManage(void) {
    if(USARTCmdData.RxTimeout) {
        USARTCmdData.RxTimeout--;
        if(USARTCmdData.RxTimeout == 0 && 
           USARTCmdData.stataus == ISRCVING) {
            // 超时，重置接收状态
            USARTCmdData.length = 0;
            USARTCmdData.stataus = WAITRECEVIE;
            USARTCmdData.Flg7E = 0;
        }
    }
}
